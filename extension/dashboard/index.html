Review history & comparison details

    New code is compared with your saved baseline within the same language family and local rule set. At least 5 solutions on each side are needed for habit trends. Samples can differ in topic and difficulty. “Not observed” does not mean a habit is gone. Missing history or source pauses habit trends.

    The “50 submissions ago” view is reconstructed from imported attempts, not a past saved review. Saved snapshots stay in this extension. The first baseline and up to 59 later reviews are retained. Demo data is never saved; incomplete syncs do not replace your baseline.

    Help & methodology

    Local checks and optional AI reviews are separate. Local checks run in JavaScript. AI review sends only your prepared selection and problem context to Google Gemini when you click Run AI review. Reports identify the sample, model, and time; they may contain errors and do not prove optimality.

    Import a JSON array, or an object with a submissions array. Required per entry: id, timestamp, title, status. Timestamp: ISO date or Unix seconds/milliseconds. Optional: titleSlug, lang, code, topics (array of strings), difficulty. Only the selected trailing calendar year is analyzed. Duplicate IDs are removed. Invalid entries are counted and skipped.

    Use Sync LeetCode while signed in, or import JSON from your own archive. A username alone cannot provide a complete code history. Source code is never executed. Sync stores it locally; optional AI review sends your selected code to Google Gemini only on request. Synced data is stored locally in this extension until you clear it. Manually imported data stays in memory. Downloads contain your code and findings.

    Reviews cover formatting, naming, structure, and a small set of algorithm patterns. These are transparent text heuristics, not an AI or AST-based code review. Style findings are suggestions. Algorithm recommendations require checking problem constraints; this app does not prove correctness, complexity, or optimality. The latest source per problem/language is reviewed to avoid counting retries as separate habits. Verdicts suggest investigation, not root causes. Python supports indentation, assignment spacing, naming consistency, function size, queue and Two Sum checks. All imported source receives basic readability checks. Common programming languages include naming checks where declarations are recognized; Python, C++ and SQL have additional rules. Missing code or topics limits findings. Accepted submissions alone cannot reveal failed attempts. Imported coverage does not prove your history is complete.
